## 修复的高危 bug（按危害排序）

**数据损坏类**
- `tomlSetKey`/`removeBlock` 用 `split('\n')` 拆 CRLF 文件再以 `\r\n` join，每行变成 `\r\r\n` —— **CRLF 行尾的 Codex/Grok 配置一经切换即整文件损坏**，且重读校验靠 trim 侥幸通过、损坏直接落盘。顺带挖出 `tomlSetKey` 带方括号节名（`'[models]'`）会拼成 `'[[models]]'` 永远匹配不到节、静默退化为文末追加的存量 bug。
- `registry.json` 损坏被静默当作空 registry 返回，任何一次保存就会**把全部 agent 定义覆盖清空**。现在区分三态：不存在/损坏（`corrupt` 原因透出，保存拒绝，设置页红字提示）/正常。
- apihub 切换的回滚有两处错：`backupFiles[i]` 下标错位（首文件缺失时回滚抛 TypeError、吞掉原始错误）；多文件写盘中途失败不回滚已写入文件（留下新旧不匹配的配置对）。改为 Map 按路径回滚，两处共用。另修 zcode `knownForms` 传空串（用户自定义选中键形态被静默改写）、BOM 剥离。

**崩溃/卡死类**
- 远程同步上传 bundle 时 ssh 提前退出 → stdin EPIPE 无监听 → **Electron 主进程直接崩溃**；`%TEMP%` 每次 `skm-bundle-*` 目录泄漏。
- Windows 侧 `git pull` 未指定合并策略：双端各自提交后 git ≥2.34 直接 fatal，同步永久失败；即使走 merge，冲突状态会留给下一轮 `add -A` **把冲突标记静默提交进历史**。现在显式 `--no-rebase` + 检测 `MERGE_HEAD` → 收集冲突文件 → `merge --abort`。
- WSL companion `pull --rebase` 冲突后仓库卡死在 rebase 中间态、之后每轮 sync 永久失败 → 检测 rebase 目录 → 收集冲突 → `rebase --abort` → 跳过 push。另补 `GIT_TERMINAL_PROMPT=0`/超时、异常兜底转 JSON 契约、`--agent` 缺参报错。
- `syncAll`/`syncToRemote`/`registry:save` 在 companion 的 await 窗口内可重入（index.lock 争用、假冲突）→ 统一 promise 链互斥。
- Docker `startEngine` 同步 resolve 让异步 error 分支成死代码，启动失败恒报成功 → 改窗口期确认模式。

**安全边界类**
- `doctor:fix` 是全库唯一信任渲染层回传路径的 handler（任意位置写文件/建 junction）→ 全部改为服务端按名字重新推导。CRLF 修复也从 `git add -A`（会卷进用户未提交草稿）改为逐文件 add。
- `link:set`/`link:remove` 补上 `skillName` 白名单（与打开动作同边界，堵目录穿越建链）。

**功能失效/误导类**
- 中文 Windows GBK：`where.exe`/`reg.exe` 直启输出按 UTF-8 解码成乱码 → 统一走 chcp 65001 通道 + 存在性校验；npm 预发布版本被误判「已是最新」→ 改 `compareSemver`；GitHub 下载缺 `--fail`（404 HTML 进 tar 解包报离题错误）→ 补上；取消更新杀不掉前 3 步的 curl/tar → onHandle 登记；更新成功后的重查窗口里取消会被 `done` 覆盖 → 加守卫。
- 导入：`con`/`nul` 等 Windows 保留名、源内嵌 symlink（删除原目录时链接静默丢失）、超长路径，现在 preview 阶段全部拦截；commit 失败降级为警告（数据已安全入 vault，不再误报导入失败）。
- winLinks 修复：跨卷 EXDEV 预检零副作用拒绝、建链失败自动回迁（不再丢文件）、回收目录同名备份加 `.N` 序号不再互相覆盖。
- 渲染层：Dashboard/ApiHub/VersionCenter 全部加「最新请求获胜」防护（旧响应覆盖新状态、ApiHub 快速切卡会写错适配器）；VersionCenter 轮询一次失败即永久停摆；Settings 的 include 输入框逐键吞逗号、端口接受小数；导入成功后不再对 junction 重新预览（必现假冲突红标）；toast 计时器互踩。
